# Configure runtime policy through environment variables and retain identity history

Mint URL and payout threshold come only from environment variables; SQLite retains the Cashu seed, Coco state, destinations and their next payout indices, identities, and a reference to the last active identity. On startup, supplied username/xpub values override the corresponding values of the last active identity, normalized destination keys reuse one counter, and matching identities are reactivated instead of duplicated; a fresh database requires both identity values. The server initializes this state automatically, so valid configuration changes require neither deleting old records nor running setup first; the CLI provides optional offline setup and verification using the same environment.

This replaces the original database-owned settings and fixed-mint/fixed-destination policy. Environment policy must be supplied even after restoring a database; the migration removes the old settings table while preserving identity, seed, destination index and Coco state. Invalid inputs or incomplete wallet state still fail explicitly rather than silently replacing a seed.
